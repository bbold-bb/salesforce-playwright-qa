# QA evals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A repeatable eval suite for the kit's two judgment jobs (drafting Test Steps, writing the spec), plus an opt-in org tier that proves a written spec rehearses green in a scratch org.

**Architecture:** `claude plugin eval` runs the model, with the kit's skill loaded as the plugin under test (and a without-skill arm), and grades with text patterns and a judge. `evals/check.py` then opens each kept run folder and runs the hard checks in code (answer key, `tsc`, `playwright test --list`, spec rules, rehearsal results), and writes one score table. `evals/run.sh` wraps both.

**Tech Stack:** Claude Code 2.1.328 `claude plugin eval` (case schema 1.1), Python 3 stdlib only (unittest for tests), TypeScript for the compile check, Playwright 1.64.1, sf CLI with a Dev Hub for scratch orgs.

**Spec:** `docs/superpowers/specs/2026-11-21-qa-evals-design.md`

## Global Constraints

- All fixture content is invented: project "Acme Support", ticket keys `ACME-<n>`, users like "Support Agent Test User". No client, employer or real-person names.
- `run.sh` always passes `--no-publish` and `--keep-temp --json`. It never publishes, writes to Jira, Slack or the ledger, or pushes.
- Pass mark: `--threshold 0.67`, applied by `check.py` to the combined score. A run with any failed hard check scores 0. A judge rubric only lowers a run's score.
- The with and without comparison is reported, never a gate.
- Prompts ask the way a teammate would. They don't paste the rule docs in. Both arms get the same workspace.
- The kit's template (`templates/qa/playwright`) is not changed. TypeScript is a dev dependency in `evals/package.json`.
- Python: stdlib only, matching the kit's other tools. No em dashes in any written file.
- Org tier: tag `org`, scratch org only, two stories (ACME-11 picklist and report, ACME-12 validation rule), records named `QA <KEY> R0 S<n>` left in the scratch org, which is deleted at the end.
- Commits are local. Push only on Ben's direction.

## Review Focus

- **A run that errored or timed out, with no output file.** Expect its hard checks to fail with "no output", scoring 0, and `check.py` to carry on with the other runs. Test in Task 2.
- **Criterion numbering written differently** ("Criterion 2", "AC 2", "criteria 2 and 3"). Expect the steps parser to read all three. Test in Task 3.
- **Kept run folders piling up in `/private/tmp`.** Expect `check.py` to delete each kept folder after reading it, unless `--keep` is passed. Test in Task 2.
- **A scratch org left behind when a run is stopped or fails.** Expect `run.sh` to delete the org on exit, including after Ctrl-C (a `trap`). Test in Task 8.
- **A spec that imports a helper `lib/` doesn't have.** Expect the `tsc` check to fail it. Test in Task 5.

### Task 2: check.py core (finding runs, combining scores, the table)

**Files:**
- Create: `evals/check.py`, `evals/lib/runs.py`, `evals/lib/score.py`, `evals/tests/test_runs.py`, `evals/tests/test_score.py`, `evals/tests/data/aggregate-sample.json` (trimmed from Task 1's real JSON)

**Interfaces:**
- Produces:
  - `runs.RunRef` dataclass: `case: str, tags: list[str], arm: str, index: int, workspace: Path | None, runner_score: float, error: str | None`.
  - `runs.load_runs(result_json: Path) -> list[RunRef]`. `workspace` is `None` when the run errored or the folder is missing.
  - `runs.open_workspace(trace_path: Path) -> Path` (chmods the kept folder and `sealed`, then returns `sealed/home/cwd`).
  - `runs.cleanup(run: RunRef) -> None`.
  - `score.Finding` dataclass: `rule: str, passed: bool, detail: str`.
  - `score.run_score(runner_score: float, findings: list[Finding]) -> float`, which is 0 if any finding fails.
  - `score.case_table(rows) -> str` (markdown: case, arm, runs, mean score, passed y/n at 0.67, with-without gap).
  - `check.HARD_CHECKS: dict[str, Callable[[RunRef, Path], list[Finding]]]`, keyed by case-name prefix (`steps-`, `spec-`, `org-`), filled by later tasks.
  - CLI: `python3 evals/check.py <aggregate.json> [--save LABEL] [--keep]`. It writes `hard-checks.json` and `scores.md` next to the JSON. With `--save` it copies both to `evals/baselines/<YYYY-MM-DD>-<model>-<LABEL>.{json,md}`. It exits 1 if any `with` arm case scores under 0.67.

- [ ] **Step 1:** Write the tests:
  - `test_load_runs_reads_arms_and_paths`: the sample has 1 case and 2 arms, so it expects 2 RunRefs with arm names `with` and `without`.
  - `test_errored_run_has_no_workspace`: set `error` and drop `tracePath` in a copy. Expect `workspace is None`.
  - `test_run_score_zero_on_any_failed_finding`: `run_score(0.9, [Finding("a", True, ""), Finding("b", False, "x")]) == 0`.
  - `test_run_score_keeps_runner_score_when_all_pass`: `== 0.9`.
  - `test_case_table_marks_pass_at_067`: means of 0.67 and 0.66 give "yes" and "no".
  - `test_cleanup_removes_kept_folder`: a temp dir is gone after `cleanup`.
- [ ] **Step 2:** Run `python3 -m unittest discover evals/tests -v`. Expected: FAIL (module not found).
- [ ] **Step 3:** Implement `runs.py`, `score.py` and `check.py` to the interfaces above. A run with `workspace None` gets one failed Finding `("output", False, "no output: <error>")` instead of calling a check.
- [ ] **Step 4:** Run the tests again. Expected: all pass. Then run `python3 evals/check.py <Task 1 JSON>`. Expected: a `scores.md` with the smoke case.
- [ ] **Step 5:** Commit: `evals: check.py core`.

### Task 3: Fixtures and the Test Steps checker

**Files:**
- Create: `evals/fixtures/acme-support/project.md`, plus `stories/ACME-1{1..6}.md`, `builds/ACME-1{1..6}-build.md`, `approved/ACME-1{1..6}.md` and `keys/ACME-1{1..6}.json`
- Create: `evals/lib/steps_check.py`, `evals/tests/test_steps_check.py`, `evals/tests/test_fixtures.py`, `evals/tests/data/steps-good.md`, `evals/tests/data/steps-bad-*.md`

**Interfaces:**
- Produces:
  - Key JSON: `{"ticket": "ACME-11", "criteria": {"1": {"tags": ["Video"], "where": "step"}, "4": {"tags": [], "where": "other", "other": "ACME-14"}}, "users": ["Support Agent Test User"], "forbidden": ["Escalated"], "max_flows": 1}`. Where `where` is `"step"`, the criterion must be proven by a step. Where it's `"other"`, Coverage must name the other ticket. Where it's `"build"`, the build check.
  - `steps_check.Step`: `number: int, flow: str | None, user: str | None, criteria: list[int], tag: str`.
  - `steps_check.Draft`: `steps: list[Step], coverage: dict[int, str], flows: dict[str, str]`, where `flows` maps a flow id to its user.
  - `steps_check.parse_steps(text: str) -> Draft`.
  - `steps_check.check_steps(draft: Draft, key: dict, text: str) -> list[Finding]` (`text` is the raw draft, for `forbidden-absent`), with rule names `build-check-first`, `step-has-tag`, `step-has-criterion`, `coverage-complete`, `coverage-no-extra`, `tag-matches-key`, `allowed-users`, `forbidden-absent`, `other-ticket-named`, `max-flows`.

The six stories follow the design's table, in that order. ACME-16 is the drift trap: its build sub-task sets a value list missing one value the story's criterion names, and the key's `forbidden` holds the build's wrong replacement value. Each `approved/` file is the correct Test Steps in the kit's template format, written to pass `check_steps` against its own key.

- [ ] **Step 1:** Write the tests:
  - `test_parse_good_draft`: steps 1 to 5, flow F1 with its user, tags, and Coverage for 1 to 5.
  - `test_parse_criterion_variants`: "Criterion 2", "AC 2" and "criteria 2 and 3" give `[2]`, `[2]` and `[2, 3]`.
  - One test per rule against a `steps-bad-<rule>.md` file, each expecting exactly that rule to fail.
  - `test_fixtures.test_every_approved_passes_its_key`: each `approved/` file passes `check_steps` against its key.
  - `test_fixtures.test_no_real_names`: grep the fixtures for each word in a local, gitignored deny list (`evals/tests/deny-words.txt`), case-insensitive, whole word. Expect no hits.
- [ ] **Step 2:** Run the tests. Expected: FAIL.
- [ ] **Step 3:** Write the fixtures, then `parse_steps` and `check_steps`. Parse by the kit template's line shapes: `<n>. ... [Tag]`, `Flow F<n>, as <user>`, and a `Coverage` heading followed by `- Criterion <n>: ...` bullets. Match case-insensitively, and accept `##`/`**` decoration.
- [ ] **Step 4:** Run the tests. Expected: all pass.
- [ ] **Step 5:** Commit: `evals: fixtures and Test Steps checker`.
